1. Resumen del Proyecto

Motor Agéntico es un dashboard local de costos y actividad para agentes de IA. Lee transcripts de Claude Code (~/.claude/projects), Codex (~/.codex) y Qwen Code (~/.qwen) en solo lectura, calcula el gasto "equivalente API" y señala fugas de tokens.


Principio fundamental: Las fuentes (~/.claude, ~/.codex, ~/.qwen) son SOLO LECTURA. Todo estado propio vive en ./data/. No usa claves API, binda solo a 127.0.0.1:8081.

Tech stack:

  • Backend: Node.js ≥ 20, Fastify, SQLite (better-sqlite3, WAL)
  • Frontend: React 18, Vite 5, Tailwind CSS 3, Recharts (modular: components/ + pages/)
  • Tests: Vitest (96 tests, 16 archivos)
  • Package manager: pnpm 11
  • Lenguaje: TypeScript 5.9 (strict mode)

Flujo de datos

  1. Descubrimiento: Cada adapter encuentra sus transcripts (Claude: *.jsonl, Codex: rollout-*.jsonl)
  2. Ingesta incremental: Solo re-lee líneas nuevas (offset por archivo con size/mtime)
  3. Normalización: Cada adapter convierte a UsageEvent común
  4. Costo: Se calcula en ingesta con costForEvent() usando pricing.json
  5. DB: SQLite con WAL, tablas: sessions, usage_events, skills_usage, memory_nodes, ingest_offsets
  6. API: Endpoints leen de la DB y devuelven JSON

5. Problemas Detectados

✓ Resuelto — App.tsx ya no es un monolito

web/src/App.tsx es ahora un shell de 48 líneas. Las páginas, componentes, hooks, tipos y utilidades viven en módulos separados.

✓ Resuelto — Config.json incluye waste

data/config.json contiene los umbrales completos y downgradePaths. La compatibilidad con configuraciones antiguas está cubierta: al guardar, se persiste el bloque completo.

✓ Resuelto — SQLite migrado a better-sqlite3

Se eliminó node:sqlite y createRequire. better-sqlite3 conserva WAL y abre la DB existente; las pruebas cubren migración, transacciones y cierre.

✓ Resuelto — PUT /api/pricing y PUT /api/config validados

Se validan números finitos no negativos, claves y modelos no vacíos, y mapas de rutas/agentes. Las entradas inválidas devuelven 400 con un mensaje visible en Configuración.

✓ Resuelto — Memoria con upserts condicionados

refreshMemoryNodes() actualiza solo nodos cambiados y elimina únicamente rutas que ya no existen.

✓ Resuelto — CodexAdapter usa import estático

CodexAdapter.parseSession() usa readFileRO desde el import estático, sin carga dinámica innecesaria.

🟢 Bajo — Reportes sin limpieza automática

Cada ingesta genera un data/reports/run-<ts>.json. No hay mecanismo de rotación o limpieza. Con el tiempo pueden acumularse cientos de archivos.

✓ Resuelto — Cierre limpio para ingestas

SIGINT y SIGTERM cierran Fastify y SQLite una sola vez; los logs son JSON y no incluyen cuerpos ni prompts.

7. Sugerencias de Mejora

7.1. ~~Romper el monolito del frontend~~ ✓ Hecho

Implementado: App.tsx descompuesto en módulos de páginas, componentes, hooks, tipos y utilidades.

web/src/
├── App.tsx          ← 48 líneas (solo shell + tabs)
├── types.ts         ← interfaces compartidas
├── hooks.ts         ← useApi, refreshAll, tick system
├── utils.ts         ← usd(), compact(), pct()
├── constants.ts     ← AMBER, REFRESH_MS, INLINE_STYLES
├── components/      ← 7 componentes reutilizables
└── pages/           ← 7 páginas independientes

7.2. ~~Agregar un linter~~ ✓ Hecho

Biome está configurado en modo comprobación mediante pnpm lint y se ejecuta en el workflow de CI.

7.3. ~~CI/CD con GitHub Actions~~ ✓ Hecho

El workflow existente ejecuta typecheck, lint, tests y build web en Node 22.

name: CI
on: [push, pull_request]
jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: pnpm/action-setup@v4
      - uses: actions/setup-node@v4
        with: { node-version: 22, cache: pnpm }
      - run: pnpm install
      - run: pnpm typecheck
      - run: pnpm lint
      - run: pnpm test
      - run: pnpm build:web

7.4. ~~Graceful shutdown~~ ✓ Hecho

server.ts instala manejadores idempotentes para SIGTERM y SIGINT y delega el cierre a app.close().

7.5. ~~Validación de pricing~~ ✓ Hecho

validatePricing() y validateConfig() validan el límite de confianza antes de persistir y responden 400 ante errores.

  • Cada modelo tiene input y output como números ≥ 0
  • No hay claves vacías
  • Estructura coincide con Pricing interface

7.6. ~~Paginación en /api/activity~~ ✓ Hecho

/api/activity devuelve { days, nextCursor }, limita a 100 resultados y filtra por proyecto, agente o modelo con cursor ended_at,id.

7.7. ~~Exportar datos~~ ✓ Hecho

GET /api/export?format=csv|json descarga sesiones y eventos de uso con cabeceras de archivo y CSV escapado. Nunca incluye prompts.

7.8. ~~Buscador de sesiones~~ ✓ Hecho

La página Actividad filtra por metadatos, ofrece “Cargar más” y busca prompts bajo demanda desde transcripts de solo lectura, sin persistirlos.
